### Anti-Defensive-Programming

Prefer the **smallest direct fix** for the reported issue.

* Do not add speculative guards, validation, fallbacks, error handling, compatibility branches, abstractions, or edge-case handling unless required by the actual bug, existing behavior, or explicit requirements.
* Do not patch around failures with additional conditions, workarounds, or special cases. **Find and fix the root cause instead of stacking patches.**
* Keep tests proportional to the change. Add only tests necessary to verify the requested behavior; do not expand tests for hypothetical or unrelated scenarios.
* A test failure does not justify adding more defensive code by itself. First determine the actual cause.
* **Do not turn a local bug fix into a defensive-programming project. When the requested behavior works with a simple fix, stop.**
